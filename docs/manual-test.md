# 手動テスト手順（マーカー認識 → クロップ算出 → OBS への適用、台形補正を含む）

Phase 1 の実験スクリプトを使って、統合フロー（[PLAN.md](../PLAN.md) 8章）と同じ流れを手動で実行する手順。
Phase 2 の `cli.py run` を作る前に、何度か繰り返して動作を確かめるために使う。

- **補正なし**（[手順（1 回分）](#手順1-回分)）: マーカーの外側の四隅を囲む矩形でクロップする。カメラが対象面にほぼ正対している場合。
- **台形補正を行う場合**（[台形補正を行う場合](#台形補正を行う場合)）: 射影補正（obs-shaderfilter）で正対化してから、補正後の矩形でクロップする。カメラが斜めから撮っている場合（[PLAN.md](../PLAN.md) 15章）。

## 準備

- `config.toml` の `[camera]`、`[target]`、`[camera.controls]`、`[layout]` が設定済みであること（[config.example.toml](../config.example.toml)）。
- マーカーを印刷しておく。

```sh
.venv/bin/python experiments/e4_aruco.py markers --size-mm 30   # experiments/out/markers/ に PDF と PNG
```

  - 等倍（100%、ページに合わせない）で印刷し、ページ下の 50mm のスケールを定規で確認する。
  - 灰色の線で切り取る。白い余白（quiet zone）は残す。

## 手順（1 回分）

| # | OBS | 操作 | コマンド |
|---|---|---|---|
| 1 | 終了中 | マーカーを置く | — |
| 2 | 終了中 | 配置とピントの確認（省略可） | `.venv/bin/python experiments/e4_aruco.py snap` |
| 3 | 終了中 | 計測とクロップ値の計算 | `.venv/bin/python experiments/e4_aruco.py measure --runs 10 --label test1` |
| 4 | — | OBS を起動する | — |
| 5 | 起動中 | 起動後もカメラのコントロールが保持されているかの確認（省略可） | `.venv/bin/python experiments/e4_aruco.py controls check` |
| 6 | 起動中 | クロップを OBS に適用する（websocket） | `.venv/bin/python experiments/e4_aruco.py apply --yes` |
| 7 | 起動中 | シーンアイテムを自動配置する | `.venv/bin/python experiments/e5_layout.py apply --yes --anchor top-center [--transition]` |
| 8 | 起動中 | 目視で確認し、マーカーを片付ける | — |

### 1. マーカーの置き方

- 切り取りたい範囲の四隅に 1 枚ずつ置く。マーカーの黒い四角の角を範囲の角にぴったり合わせ、マーカーは範囲の内側に置く。
- ID と隅の組み合わせ、マーカーの向きは自由（画像上の座標から四隅を決める）。
- 範囲の辺をカメラ画像の辺となるべく平行にする。傾きが幅・高さの 1% を超えると警告が出る（処理は続く）。
- マーカーが浮いたり、手やペンで隠れたりしないようにする。

### 2. snap（配置とピントの確認）

- 1 枚撮影し、検出できた ID と各マーカーの大きさ（ピクセル）を表示する。
- `experiments/out/e4-<時刻>-snap.jpg` と `-snap-overlay.jpg`（検出結果を重ねた画像）を保存する。
- 4 枚とも検出されない場合は、置き方、照明（反射）、ピントを見直す。

### 3. measure（計測）

- `--runs` 回、カメラを開き直して計測する（1 回あたり約 2.4 秒）。
- 結果:
  - 各回のクロップ値と、フレーム間のばらつき（角の標準偏差）
  - 集計（各値の最小・最大・ばらつき）と、±1px 以内かどうかの判定（OK / NG）
  - 画像上の四隅と ID の対応
- 保存するもの:
  - `experiments/out/e4-last.json`: 最後の計測結果。手順 6 の `apply` はこれを使う
  - `e4-<時刻>-overlay.jpg`: 検出結果とクロップ矩形を重ねた画像
  - `e4-<時刻>-corners.png`: 各マーカーの外側の角を拡大した画像。緑線がクロップの境界、赤点が検出した角
- **NG のときも `e4-last.json` は書き出される**（終了コード 1）。そのまま手順 6 に進むと NG の値が適用されるので、計測し直す。

### 4. OBS の起動

- 計測（手順 2・3）は OBS の終了中に行う。OBS がカメラを使っていると開けないため。
- 1 回のテストごとに、OBS の終了と起動が 1 回ずつ必要になる。

### 6. apply（クロップの適用）

- 適用前に次を確認し、問題があれば中断する（`--force` で警告のみにできる）。
  - Crop/Pad より前に有効なフィルタがないこと
    - 射影補正のフィルタ（`Perspective`）が先頭にある場合は、それだけは前段に許す。ただし有効で単位行列でない（台形補正を適用中の）場合は中断する。補正なしで使うときは、OBS のフィルタ画面で `Perspective` を無効（目のアイコンをオフ）にしておく
  - ソースの `device_id` が計測したカメラと同じこと
  - ソースの素のサイズが計測時の解像度と同じこと（確認のため Crop/Pad を一瞬無効にする。映像が一瞬切り替わる）
- 適用後、ソースのサイズがクロップ値と一致するかを確認し、スクリーンショットを `e4-<時刻>-applied.png` に保存する。
- 適用前のフィルタ設定を `e4-crop-before-<時刻>.json` に保存する。
- 設定は websocket で変更する（シーンコレクションの JSON は直接書き換えない）。変更は OBS の終了時に OBS 自身が保存する。

### 7. layout（シーンアイテムの自動配置）

- クロップ後のソースを、アスペクト比を保ってキャンバスの内側に収まる最大の大きさ（縦または横がいっぱい）にし、アンカーに合わせる。
  - `top-center`: 上辺中央を上辺中央に（**この手順の既定。中央揃え**）
  - `top-left`: 左上を左上に（左寄せ）
  - `top-right`: 右上を右上に（右寄せ）
  - 縦がいっぱいになる場合（クロップが横長でもキャンバスより縦長寄りの場合）は、それぞれ中央揃え・左寄せ・右寄せになる。例: 2110×1630 のクロップでは、表示範囲は `top-center` が (522, 0)–(3318, 2160)、`top-left` が (0, 0)–(2796, 2160)、`top-right` が (1044, 0)–(3840, 2160)。
- この手順では `--anchor top-center` を指定する。省略すると `config.toml` の `[layout] anchor` を使う（左寄せ・右寄せにしたい場合は `--anchor` を変える）。
- `status` で、変更せずに現在の値と配置後の値を確認できる。

```sh
.venv/bin/python experiments/e5_layout.py status --anchor top-center
```

- 適用前の変換を `e5-transform-before-<時刻>.json`、シーンのスクリーンショットを `e5-<時刻>-scene.png` に保存する。
- **Studio モードではプレビューにのみ反映される。** プログラムへは OBS の画面でトランジションするか、`--transition` を付ける。配信中・録画中は出力が切り替わるので注意する。
- 回転・境界（bounds）を使うシーンアイテムには適用できない（エラーで中断する）。

## 台形補正を行う場合

カメラが対象面に正対しておらず、対象面が台形（や少し回転した四角形）に写る場合の手順。
外側の四隅から射影変換の行列を求め、OBS のシェーダーフィルタ（`Perspective`）で正対化してから、
補正後の矩形 R でクロップする（[PLAN.md](../PLAN.md) 15章、[PLAN_perspective.md](PLAN_perspective.md)）。

### 準備（初回のみ）

- obs-shaderfilter を導入する（[install-shaderfilter.md](install-shaderfilter.md)）。
- カメラのソースの先頭に射影補正のフィルタを追加する（OBS 起動中。シーンコレクションが変わる）。

```sh
.venv/bin/python experiments/p1_perspective.py install --yes   # 単位行列（素通し）で追加
.venv/bin/python experiments/p1_perspective.py status          # 版・エラー・フィルタの順序の確認
```

  - フィルタの順序は `[0] Perspective`、`[1] Crop/Pad`、（以降はほかのフィルタ）になる。
  - `config.toml` の `[perspective]` を確認する（`filter_name`、`aspect_source` など。[config.example.toml](../config.example.toml)）。
    縦横比は既定（`aspect_source = "markers"`）ではマーカーから推定するので、対象面の実寸を測る必要はない。
- マーカーは補正なしと同じものを使う（[準備](#準備)）。

### 手順（1 回分）

| # | OBS | 操作 | コマンド |
|---|---|---|---|
| 1 | 終了中 | マーカーを置く（実寸の測定は任意） | — |
| 2 | 終了中 | 配置とピントの確認（省略可） | `.venv/bin/python experiments/e4_aruco.py snap` |
| 3 | 終了中 | 計測と、行列・補正後の矩形 R の計算 | `.venv/bin/python experiments/p3_perspective.py measure --label test1` |
| 4 | — | OBS を起動する | — |
| 5 | 起動中 | 射影補正のフィルタの状態確認（省略可） | `.venv/bin/python experiments/p1_perspective.py status` |
| 6 | 起動中 | 行列と R を OBS に適用する（websocket） | `.venv/bin/python experiments/p3_perspective.py apply --yes` |
| 7 | 起動中 | 補正の結果を確認する（再検出） | `.venv/bin/python experiments/p3_perspective.py verify --yes` |
| 8 | 起動中 | シーンアイテムを自動配置する | `.venv/bin/python experiments/e5_layout.py apply --yes --anchor top-center [--transition]` |
| 9 | 起動中 | 目視で確認し、マーカーを片付ける | — |

### 1. マーカーの置き方（と、任意で実寸）

- 置き方は補正なしと同じ（[1. マーカーの置き方](#1-マーカーの置き方)）。ただし、範囲の辺がカメラ画像の辺と平行でなくてよい（傾きは補正される）。
- マーカーの四隅は長方形になるように置く（縦横比をマーカーの形から推定するため、四隅が長方形でないと補正後の形が歪む）。
- 実寸の測定は任意。測る場合（照合したい、または `aspect_source = "target_mm"` で使う場合）:
  - マーカーの黒い四角の外側の角どうしの距離を、上・下・左・右の 4 辺とも mm で測る。上と下、左と右が同じ長さであること。違う場合は置き方を直す。
  - `config.toml` に書く: `[perspective] target_mm = [幅, 高さ]`（例: 上下 250mm・左右 174mm なら `[250, 174]`）。`aspect_verify = true`（既定）なら、マーカーからの推定値と照合して 1% を超えると警告する。
  - 寸法の分かっている物（A4 用紙 297×210mm など）を対象面にするなら、その寸法を書けばよい。
- 制限:
  - 面内の回転（画像の中で四角形が回っている角度）は ±35° まで。超えると四隅を正しく割り当てられないため、手順 3 が中断する。
  - 射影による傾き（台形）が大きいと、補正で画質が落ちる。辺の傾きが `max_skew_warn_deg`（既定 25°）を超えると警告が出る。

### 3. measure（計測と計算）

- カメラを開いて 20 フレーム（`--frames`）計測し、外側の四隅から補正後の矩形 R と行列を求める。
- 表示するもの:
  - 有効なフレーム数（4 枚とも検出できたフレーム）と、外側の四隅の座標
  - 辺の傾き（上・右・下・左、度）と、補正前の外接矩形
  - 縦横比: 採用した値（既定はマーカーの形から推定した値）と、推定の残差・フレーム間のばらつき。`target_mm` があれば実寸の比との差
  - R（補正後の矩形。Crop/Pad にそのまま使う）と行列 M
  - 予測: シェーダーと同じ計算で補正した画像でマーカーを再検出した結果（四隅の誤差、マーカーの縦横比の偏り、四隅の縦横比の差）
- 保存するもの:
  - `experiments/out/p3-last.json`: 計測と計算の結果。手順 6・7 はこれを使う
  - `p3-<時刻>-overlay.jpg`: 補正前の検出結果
  - `p3-<時刻>-rectified-sim.jpg`: 補正の予測（緑の枠が R）。対象面の辺がまっすぐ・水平垂直になっていることを確認する
- 判断の目安:
  - 推定の残差が 1% を超えると警告が出る。紙の浮き・反り、マーカーの検出不良を疑い、置き方を見直す。
  - `target_mm` がある場合、推定値との差が 1% を超えると警告が出る。実寸の測り間違い、マーカーの置き方（範囲の角とずれている）、紙の浮き・反りを疑う。**対象面を替えたときは `target_mm` を更新するか削除する**（前の対象面の寸法が残っていると、この警告が出る。採用値はマーカーの推定値なので補正には影響しない）。
  - `補正後の矩形がフレーム…に収まらないため…縮小しました` は、補正後の矩形 R がフレーム（端から 64px の内側）に入りきらず、少し縮小したことを示す（補正は可能だが実効解像度が少し下がる）。カメラを引くか、対象面を中央に寄せると解消する。
  - 予測の四隅の誤差が 1px を超える場合は、検出が不安定。照明・ピント・マーカーの貼り方を見直す。
  - 「傾き」の警告（補正前の辺が軸と平行でない）は台形補正では想定どおりなので、気にしなくてよい。

### 5. status（フィルタの状態確認）

- `up_to_date` が `true`（シェーダーの版がリポジトリと同じ）、`last_error` が `null`、`order_problems` が空であること。
- 版が古い場合は `p1_perspective.py reinstall --yes` で作り直す（行列と有効状態は引き継ぐ）。

### 6. apply（行列と R の適用）

- 適用前に次を確認し、問題があれば中断する（`--force` で警告のみにできる）。
  - フィルタの順序（`Perspective` が先頭で、`Crop/Pad` との間にほかの有効なフィルタがない）
  - ソースの `device_id` が計測したカメラと同じこと
  - ソースの素のサイズが計測時の解像度と同じこと（確認のため Crop/Pad を一瞬無効にする。映像が一瞬切り替わる）
- `Perspective` に行列を設定して有効にし、`Crop/Pad` に R を設定する（`relative=false`）。ソースのサイズが R と一致するかを確認する。
- 適用前の状態（`Perspective` の行列・有効状態、`Crop/Pad` の設定）を `p3-before-<時刻>.json` に保存する。スクリーンショットは `p3-<時刻>-applied.png`。

### 7. verify（補正の確認）

- Crop/Pad を一時的に無効にし、補正後の画像全体を原寸（3840×2160）で撮って、マーカーを再検出する。
  - **数秒間、出力（プレビュー・プログラム）にクロップ前の画像が映る。配信中・録画中には実行しない。**
  - 原寸のスクリーンショットは取得に数秒かかる。
- 表示するもの:
  - 外側の四隅と R の四隅の差（最大）。**1px 以内なら OK**（終了コード 0。`--tol` で変えられる）
  - 各マーカーの縦横比（1 に近いほどよい。紙の浮き・反りやレンズ歪みがあると 0.5% 程度ずれることがある）
  - 四隅の縦横比と採用値の差
- 保存するもの: `p3-<時刻>-verify-full.png`（補正後の全体）、`p3-<時刻>-verify-corners.png`（外側の角の拡大）
- 四隅が**そろって外側（または内側）に数 px ずれる**場合は、計測時と OBS の使用時でカメラのピントが変わり、像の大きさが変わった可能性が高い（オートフォーカスのとき。P3 の手動テストで 0.24%、4K で 3〜4px）。補正の形（縦横比、直線）は正しい。±1px にしたい場合は、`config.toml` の `[camera.controls]` でフォーカスを固定し（`focus_automatic_continuous = 0`、`focus_absolute = <値>`）、`e4_aruco.py controls set --yes` で設定してから計測し直す。

### 8・9. 自動配置と目視確認

- 自動配置は補正なしの手順 7 と同じ（[7. layout](#7-layoutシーンアイテムの自動配置)）。
- 目視で確認すること:
  - フレームの四隅にマーカーの黒い四角の外側の角が来ている
  - 対象面の直線（紙・板の縁、マーカーの辺）がまっすぐで、水平・垂直になっている
  - 比率が実寸どおりに見える（マーカーが正方形に見える）
- Studio モードでは、トランジションしてプログラムにも反映されたことを確認する。

### 補正なしとの切り替え

- 台形補正 → 補正なし: OBS のフィルタ画面で `Perspective` を無効にしてから、補正なしの手順を行う。フィルタごと外す場合は `p1_perspective.py remove --yes`。
- 補正なし → 台形補正: 台形補正の手順を行う（手順 6 の `apply` が `Perspective` を有効にする）。
- 適用前の状態に戻す: 下の「元に戻す」の `p3_perspective.py restore`。

## 元に戻す

```sh
# 補正なし: クロップ
.venv/bin/python experiments/e4_aruco.py restore-crop experiments/out/e4-crop-before-<時刻>.json --yes
# 台形補正: 射影補正の行列・有効状態とクロップ
.venv/bin/python experiments/p3_perspective.py restore experiments/out/p3-before-<時刻>.json --yes
# 共通: シーンアイテムの配置
.venv/bin/python experiments/e5_layout.py restore experiments/out/e5-transform-before-<時刻>.json --yes [--transition]
```

## 試すとよい条件

- マーカーの位置を変える（広い範囲・狭い範囲、縦長・横長）
- マーカーの向き、ID と隅の組み合わせを変える
- 照明を変える（反射が出る、暗い）
- `[layout] anchor` を 3 種類とも試す
- 範囲の一部が画面からはみ出す（範囲を画面内に切り詰めて警告を出す）
- 台形補正: カメラの傾きを変える（台形の強さ、面内の回転）、`target_mm` をわざと間違えて縦横比の照合の警告が出ることを確かめる、`aspect_source = "target_mm"`（実寸の比を使う）と既定の `markers` で結果を比べる
