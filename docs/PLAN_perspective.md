# 拡張企画: OBS シェーダーフィルタによる射影補正（台形補正）— アウトライン

> ステータス: アウトライン v3（2026-11-15 レビュー反映。`PLAN.md` 15章に取り込み、Phase 1 の基礎技術確認として P0〜P3 を実施する）
> 用語: 「対象面」は撮影対象の板（マーカーを置く平面）。OBS のキャンバス（出力の解像度）と区別するため、`canvas_mm` を `target_mm` に改名した。
> 位置づけ: `PLAN.md`（本体企画）の拡張。本体の 0章の方針（実環境の検査を優先する、移植性を考慮する、ユーザー確認のルール、バックアップ）をそのまま引き継ぐ。

---

## 1. 目的と使用前提

### 目的
- カメラを正対させられない固定設置でも、台形歪みを補正した映像を OBS 内で得る。
- ArUco マーカーで得た四隅から射影変換の行列を求め、OBS のシェーダーフィルタに websocket で渡す。
- 補正のオン・オフは OBS 内で切り替える。

### 使用前提（本体と共通）
- スタジオなど、固定カメラの撮影・配信環境で使う。
- 移動するカメラや被写体は対象としない。
- フレームレートより解像度を優先する。

### スコープ外
- レンズ歪み（樽型・糸巻き型）の補正
- OBS 以外のアプリへの補正後の映像の提供（GStreamer と v4l2loopback による方式は今回は扱わない）
- 配信中の継続的な自動再計測

## 2. 決定事項

| 項目 | 決定内容 |
|---|---|
| 補正の実行場所 | OBS 内のシェーダーフィルタ（obs-shaderfilter） |
| 計測 | 本体と同じ方式A（OBS 起動前に計測し、カメラを解放する） |
| 渡す値 | 出力から入力への逆行列 H⁻¹。正規化した UV 座標系で求め、個別の float として渡す |
| 補正後のアスペクト比 | **既定はマーカーの正方形の情報から推定する（`markers`、2026-11-15 変更）。** 対象面の実寸（`target_mm`、W×H mm）は任意で、指定すれば照合に使う。実寸から決める `target_mm` モードも選べる（4.2） |
| 本体の制約との関係 | この拡張を有効にすると、本体の「台形補正なし」の制約が外れる |
| 動作モード | 射影補正は正対化のみ。補正後の矩形 R（フレーム内の軸平行・整数ピクセルの矩形）に四隅を写し、切り出しは既存の Crop/Pad（R）、配置は本体 14章の自動配置で行う（`PLAN.md` 15.3、2026-11-15 決定） |
| 実施時期 | Phase 1 に基礎技術確認（P0〜P3）として加える（2026-11-15 決定） |
| GUI での四隅の手動微調整 | Phase 3 に含める（2026-11-15 決定） |

## 3. 処理フロー

```
 1. （本体と同じ）カメラの解決、フォーマットの決定、キャプチャ、四隅の検出
 2. 射影変換を計算する
    - 入力: 外側の四隅（ピクセル座標）、ソースの解像度、縦横比
      - 縦横比は `aspect_source` に従って決める（4.2）
      - `target_mm` の場合は対象面の実寸から、`markers` の場合は各マーカーの全角（16点）から推定する
    - 出力: 正規化した逆行列 H⁻¹、縦横比とその決め方、推定時は残差
 3. 計測結果を保存する（四隅と行列）
 4. カメラを解放して OBS を起動し、接続を待つ（本体と同じ）
 5. 整合チェックを行う（7章）
 6. SetSourceFilterSettings で行列をシェーダーフィルタに設定する
 7. SetSourceFilterEnabled で補正を有効にする
 8. Crop/Pad に R を設定する（本体と同じ set_crop）
 9. シーンアイテムを自動配置する（本体 14章）
10. 微調整する（9章）
```

## 4. 射影変換の計算（`vision/homography.py`、OS 非依存）

### 4.1 行列の計算

1. **入力側の四点**: 外側の角 P0〜P3 を、ソースの解像度で割って正規化する（0〜1）。
2. **出力側の四点**: 補正後の矩形 R の四隅を、正規化座標で表す。
   - 矩形の縦横比 r（= 高さ / 幅）は 4.2 で決める。
   - R はフレーム内の軸平行・整数ピクセルの矩形とする。大きさは、再サンプリングで縮小しないよう補正前の四辺のうち長い方の辺に合わせ、フレームに収まらなければ縮小して警告する。位置は補正前の四隅の外接矩形の中心に合わせる（`PLAN.md` 15.3）。
   - 出力フレームとのアスペクト比の差は、Crop/Pad で R を切り出したあと本体 14章の自動配置（`contain` 相当）で扱う。
   - 正規化は `(x + 0.5) / W`、`(y + 0.5) / H` とする（本体 7.4 の画素中心の座標とシェーダーの UV をそろえる）。
3. `cv2.getPerspectiveTransform(出力側の四点, 入力側の四点)` で、出力から入力への行列 M（= H⁻¹）を直接求める。
4. M を `M[2][2] = 1` になるよう正規化する。
5. 検証:
   - M で出力側の四点を写すと入力側の四点に戻ること（誤差が 1e-6 以下）
   - 行列が退化していないこと（行列式が 0 に近くない）
   - 極端な傾きでないこと（しきい値を超えたら警告）

シェーダー内では、出力の UV 座標 (u, v) に対して次の計算を行う。

```
[x, y, w]ᵀ = M · [u, v, 1]ᵀ
入力の UV = (x / w, y / w)
```

### 4.2 縦横比の決め方（`aspect_source`）

| 値 | 決め方 | 用途 |
|---|---|---|
| `markers`（**既定**、2026-11-15 変更） | マーカーが正方形であることを使って推定する（下記） | 通常の運用。対象面の実寸を測らなくてよい（P3 で実寸との差 −0.096%） |
| `target_mm` | 設定の `target_mm` から r = H_mm / W_mm とする | 対象面の寸法が分かっている場合（例: A4 用紙）や、厳密にしたい場合 |

- 縦横比（実寸）は計測時に行列を計算するためだけに使う。シェーダーが受け取るのは行列だけで、`target_mm` は OBS に保存されない。使うのは比だけで、絶対値（mm）は使わない。
- 機材の配置が変わらず前回の行列を再利用する場合は、縦横比の情報は不要。

#### `markers` での推定方法
- 原理: 正しい縦横比で補正すれば、各マーカーは正方形に写る。
  - 射影の成分（遠近感）は外側の四隅で決め、縦横比だけをマーカーの正方形から決める。未知数は r の1つだけになる。
  - マーカー1つだけで変換全体を求める方法は、小さな正方形から画面全体の遠近感を外挿することになり誤差が大きいので、採用しない。
- 手順:
  1. 外側の四隅を 1 × r の矩形に写す射影変換 H_r を考える。
  2. H_r で各マーカーの4つの角を写し、補正後の各マーカーの縦横比 a_i(r)（縦の辺の平均 / 横の辺の平均）を求める。
  3. `Σ (log a_i(r))²` を最小にする r を求める。**P2 で実装: 閉じた形で求める。** 1 × r の矩形へ写す変換は「単位正方形へ写す変換 H_1 のあとに縦を r 倍する」ことと同じなので、辺を軸へ射影した長さで a_i を測れば a_i(r) = r · a_i(1) となり、最小解は `r = exp(−mean(log a_i(1)))`（反復の最適化は不要）。
  4. 複数フレームで推定した r の中央値を最終値とする。
- 出力:
  - 推定した r
  - 残差: 推定した r での各マーカーの `|log a_i|` の最大値と平均値、フレーム間のばらつき
- 判定:
  - 残差が `aspect_residual_warn`（既定 1%）を超えたら警告する。紙の反り、マーカーの検出不良、強いレンズ歪みの兆候として扱う。
  - 推定に使えるマーカーが揃わないフレームは除外する（本体 7.4 の `min_valid` に従う）。
- 精度の見込み: サブピクセル補正で角の誤差が 0.1〜0.3px、マーカーが 50px のとき、4 つのマーカーの縦横を使って 0.3% 程度（1080px の辺で約 3px）。精度を上げたい場合はマーカーを大きくするのが最も効果的。
  - **P2 の結果（合成画像）:** マーカー約 50〜60px で誤差は多くの条件で 0.2% 以下だが、傾きによっては 0.5% 前後の系統誤差が出た（フレームを増やしても減らない）。約 120px なら 0.3% 以下。`markers` を使う場合はマーカーが 100px 以上に写る大きさにする（当環境の 30mm マーカーは 4K で約 230px）。

#### 照合（`aspect_verify`）
- `target_mm` があり `aspect_verify = true`（既定）のとき、マーカーからの推定値と実寸の比を比較する。どちらの `aspect_source` でも行う。
- 差が `aspect_verify_tol`（既定 1%）を超えたら警告する。採用する値は `aspect_source` のとおりで変えない。
- 実寸の入力ミスや、マーカーと対象面の取り付けのずれを検出するために使う。

#### 前提条件
- マーカーと対象面が同一平面上にあること（紙の反りや浮きは誤差になる）。
- マーカーの実寸は不要。使うのは「正方形である」という性質だけ。ただし、プリンタの縦横倍率の違いは誤差になる。
- レンズ歪みは補正しないため、画面の端のマーカーほど推定に偏りが出る可能性がある。

## 5. シェーダー（`shaders/perspective.shader`）

- uniform として `m00`〜`m22` の 9 個の float を宣言する。
  - `m22` は常に 1 だが、汎用性のために残す。
- 処理: 出力 UV → M → 入力 UV を求め、入力のテクスチャから色を取る。
- 範囲外の扱い: 入力 UV が 0〜1 の外になる画素は透明（アルファ 0）にする。黒にするかは設定で切り替える。
- 補間: テクスチャのサンプラー設定に従う（バイリニア補間）。
- **P0 で確認（2026-11-15、`PLAN.md` 13章）**
  - 記法: OBS 版の HLSL。`float4 mainImage(VertData v_in) : TARGET` を書き、`image.Sample(textureSampler, uv)` で入力を取る（`shaders/perspective.shader`）。
  - uniform（`uniform float m00 = 1.0;` など）は、設定の uniform 名と同じキーで値を受け取る。websocket の `SetSourceFilterSettings` で変更すると即座に反映される。
  - シェーダーの指定: `from_file` が真なら `shader_file_name` のファイル、偽なら `shader_text` の本文。**本文やファイルの中身を変えても websocket だけでは再コンパイルされない**（作成時・読み込み時・プロパティ画面の操作時のみ）。
  - コンパイルに失敗すると設定の `last_error` にエラー文が入り、映像は素通しになる。

## 7. 整合チェック（本体 9.2 の変更点）

- 変更前: 「Crop/Pad の前段にフィルタがないこと」
- 変更後: 「射影変換フィルタが先頭にあり、その前段にほかの映像フィルタがないこと」
- 追加するチェック:
  - シェーダーフィルタの種別とシェーダーの指定が、期待どおりであること
  - ソースの解像度が、計測時の解像度と一致すること（行列は正規化しているので、解像度が違うと補正の結果がずれる）

## 8. 設定（`config.toml` への追加）

```toml
[perspective]
enabled = true
filter_name = "Perspective"
shader_path = "shaders/perspective.shader"   # 本文を shader_text にインラインで書き込む（P0 で決定）
aspect_source = "markers"                     # markers（既定）| target_mm
# target_mm = [250, 174]                      # 任意。対象面の実寸（W, H）。target_mm モードでは必須
aspect_verify = true                          # target_mm があるとき、マーカーからの推定値と照合する
aspect_verify_tol = 0.01                      # 照合の許容差（比率）
aspect_residual_warn = 0.01                   # markers 推定の残差の警告しきい値
outside = "transparent"                       # transparent | black
max_skew_warn_deg = 25                        # 極端な傾きの警告しきい値
```

### CLI

| P0（完了） | 実環境の検査 | obs-shaderfilter の有無とバージョン、導入方法（PPA 版・Flatpak 版それぞれ）、設定の JSON のキー、uniform がプロパティになる条件、シェーダーの指定方法 |

## 11. リスク

| リスク | 内容 | 対策 |
|---|---|---|
| プラグインへの依存 | obs-shaderfilter のバージョンや OBS のバージョンとの互換性。Flatpak 版での導入方法 | P0 で確認する。バージョンを記録し、未導入時は明確なエラーを出す |
| 設定キーの不一致 | uniform 名とプロパティのキーの対応がプラグインのバージョンで変わる可能性 | P0 で確認し、キー名の対応を設定で変えられるようにする |
| 画質の低下 | 再サンプリングによるぼやけ。遠い側の辺は引き伸ばされ、実効解像度が下がる | 運用ではカメラをできるだけ正対に近づけ、傾きが大きい場合は警告する |
| アスペクト比の誤差（`target_mm`） | 対象面の実寸の入力ミスで、補正後の縦横比が狂う | 既定は `markers` で実寸を使わない。`target_mm` を使う場合は `aspect_verify` で推定値と照合する |
| 縦横比推定の誤差（`markers`） | 紙の反り、同一平面からのずれ、レンズ歪み、プリンタの縦横倍率の違い | 残差で警告する。マーカーを硬い板に貼り、大きめに印刷する。誤差が許容できない場合は `target_mm` を使う |
| 解像度の不一致 | 計測時と実行時でソース解像度が違うと補正がずれる | 整合チェック（7章） |
| 浮動小数の精度 | シェーダー内の float の精度 | 正規化座標で計算し、P2 と P3 で誤差を確認する |
